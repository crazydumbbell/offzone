# Rue v6 wardrobe — next-phase design, not a live shop

## Implemented vs concept (2026-09-24)

User fixed adult Rue v6 as the mascot and requested all Kiwi runtime art replaced. iOS and Android source now use 8 static Rue expression images and 4 full-body resources (from `.growth-design/mascots/2026-09-24-rue-native/manifest.json`); kiwi animation and accessible greeting wording were removed from native bundles, while the official `off` icon remains. Outfit files `01`–`03` are three **new built-in image_gen full-body concepts only**. None is selectable, earned, purchasable, or approved for release. Their entire PNG bodies are precomposed; they cannot be mixed with the existing 8 expression poses without redrawing/rigging. Do not merely recolor the current eight UI expressions and call this a modular avatar system. The paid/rewarded premise is a user direction, not a price, SKU, transaction authorization or behavioral metric decision.

## Adult creative constraints

Base sage/charcoal Rue stays free. Three variants: navy/terracotta, cream-brown/pine, lavender/charcoal-indigo. Short opaque above-knee A-line hems, adult proportion, familiar bob and face. No school uniforms, revealing costumes, youthful infantilization, cosmetic changes to rule efficacy or forced outfit flows. Include accessible art descriptions and sensible low-vision/color distinctions. All concept alpha channels retain glow and no legal/originality/similarity or hardware QA exists. Keep PNG masters, hashes and generation provenance; obtain consistently posed, clean cutout **per-state** portraits/full-body or a proper layered rig before wardrobe runtime development.

## Entry / preview / unlock / exit contract (future proposal)

1. **Entry:** Optional Wardrobe item from profile or Rue area, never a gate to Start focus or Restore access. No pop-up during failures, emergency restore, onboarding permission, or a focused session. Explicitly label Owned / Not owned / Preview; original Rue always owned.
2. **Preview:** Show the same state and side-by-side original before Equip. Closing preview restores current equipped look. Don't overwrite app Focus state when changing art; VoiceOver/TalkBack can describe outfit and ownership independent of state message. Reduced motion is the default until separately validated.
3. **Earn:** Define a finite, auditable `GrantEvent` and once-per-account eligibility only after confirming the product's meaningful voluntary action; avoid rewards for longer app blocking, streak pressure, a higher number of interrupted attempts or remaining in the app. Rewards cannot change OS restrictions, free recovery or rule status. Grant must be idempotent, recoverable offline and safely synced. Policy/UX study before deciding actual earning criteria or number of items.
4. **Purchase (not built/authorized):** If later selected, decide platform-specific digital-cosmetics IAP and localized price, approved catalog, signed/store-verified transaction ledger, idempotent fulfillment, restore across same account, refunds/revocation, Apple/Google policy review, accessibility/parental controls, account deletion and support. Never use a local boolean or reuse RevenueCat Pro/unlock-pass entitlement to grant outfits. Free base cannot disappear after refunds/account sign-out; offline fallback honors last *verified* inventory. Purchases must not replace safety restore or unlock a focus result.
5. **Persistence/exit:** `OutfitId` stable (base, navy, pine, lavender); `Inventory` contains source (`starter`, `verified_grant`, `verified_purchase`) and provenance, with explicit `equippedId` validated against owned items. Unknown/missing/refunded outfit falls back to base. Preview never mutates purchase state. User can switch back to base without forfeiting owned cosmetics. Data export/delete paths must cover future outfits, avoid mixing separate Apple/Google store receipts.

## Implementation slices / acceptance gates

- **Now:** Base Rue compiled into iOS/Android and local simulator/emulator previewed; assets were deterministically downsampled with low-alpha wash attenuation, **not clean-alpha certified**. Native QA and rights review before shipping. Wardrobe PNGs/design gallery only. Official `off` icon, Play listing, real screenshots and paid configuration unchanged.
- **Next, art proof:** One alternate outfit across 8 compact states and 4 fullbody states, same face/pose and stable trim on butter/ink + 84×96pt, delivered as a candidate skin with tested memory/bundle cost. Explicit user choice of desired variant(s). Full-body-only cards are insufficient for Home.
- **Next, free equip slice:** Implement local base + one fully tested free skin with safe migration and state-independent outfit renderer, no reward or purchase yet. Add accessible wardrobe browse/equip/revert, migration/corruption tests and full focus/free restore regression suite. Localization en primary/ko secondary.
- **Only after entitlement design approval:** Product/customer validation of reward contract and digital item sale; ledger/store policies and verified receipt/restore/refund end-to-end on devices. Separate Play/App Store publication decision. RevenueCat existing Pro config must not be silently reused for cosmetics.

**Risks:** Generated image facial/pose drift between whole-body concepts; opaque-looking halos despite alpha; licensing/similarity unreviewed; incomplete real-device Screen Time/Accessibility and animated media QA. Builds, gallery thumbnails and editor mocks are not release readiness.
