# Offzone mascot design loop

## Inputs

1. 사용자 선택과 디자인보드의 **깨끗한 원본**을 찾고 직접 본다. 카드 스크린샷이나 외부 참고 이미지를 원본으로 취급하지 않는다.
2. 현재 앱의 마스코트 호출 지점, 실제 표시 크기, 배경색, 핵심 행동, 영문·한글 문안을 확인한다. 기존 자산·매핑을 재사용할 수 있으면 재사용한다.
3. 원본에서 변하지 않아야 할 얼굴·실루엣·색·질감을 적고, 허용할 표정·동작·의상 변화를 적는다. 추측한 특징은 고정 규칙으로 만들지 않는다.

## Make and place

1. 화면/상태별 자산 매핑을 만든다. 같은 감정과 구도가 통하는 화면은 같은 자산을 쓴다.
2. 새 그림은 확인한 원본을 참조해 생성한다. 자산마다 원본 경로, 생성 지시, 파일 경로를 남긴다. 타인의 참고 이미지를 그대로 복제하지 않는다.
3. 투명 자산은 실제 알파를 확인하고, 흰색·버터색·어두운 화면 위에서 가장자리의 사각형·후광·배경 잔상을 살핀다. 문제를 화면 배경색으로 가리지 말고 자산을 고친다.
4. 실제 렌더링 크기에서 얼굴을 알아볼 수 있게 하고, 안전 영역·CTA·텍스트·터치 영역을 침범하지 않도록 배치한다. 장식이 행동을 대신 설명하게 하지 않는다.

## Screenshot review loop

대표 상태를 iOS와 Android의 **실제 실행 화면 캡처**로 검수한다. 가능한 경우 첫 화면, 집중 중, 완료/복구를 포함한다. 목업만 있으면 실제 화면 검수는 미완료로 표시한다.

| 항목 | 점수 |
|---|---:|
| 확정 원본과 같은 캐릭터로 보이는가 | 30 |
| 투명 합성·가장자리·배경이 깨끗한가 | 25 |
| 제목, 주요 행동, 마스코트의 시각적 순서가 분명한가 | 20 |
| 상태에 맞는 표정·자세와 화면 간 일관성이 있는가 | 15 |
| 축소 가독성, 대비, 접근성 설정이 유지되는가 | 10 |

각 항목에 캡처 경로와 관찰한 근거를 적는다. 총점 90/100 이상이고 캐릭터 불일치, 배경 잔상, 행동 가림, 접근성 퇴행이 없을 때 통과한다. 미달이면 가장 큰 원인 하나를 고쳐 다시 캡처·채점한다. 주관적 점수만으로 테스트나 실기기 검증을 대신하지 않는다.

## Handoff

변경된 자산/화면, 확인한 캡처, 남은 미검증 항목, 다음 수정 한 가지를 오케스트레이터와 Room UX에 전달한다. 새 사용자 피드백이 오면 그 부분부터 루프를 재개한다.
